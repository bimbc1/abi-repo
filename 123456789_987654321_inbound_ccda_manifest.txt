ixed. Previously, if the dropdown update failed because the database was down, the error was only written to the logs as a warning, so no retry happened and no alert email was sent. I updated update_partner_dropdown() so it now receives the Lambda event and context. If it fails with a DatabaseConnectionError, it calls invoke_retry_handler and route_critical_failure_notification, the same way the per-record loop handles failures, so the team gets a retry and an alert email. The alert call is wrapped in a try/except so a problem sending the email cannot crash the Lambda. Any other error in the dropdown update, such as a dashboard read or save error, is still only logged as a warning, because the dropdown is a side task and should never stop or slow down file processing.
